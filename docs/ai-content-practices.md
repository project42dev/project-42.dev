# AI content practices

Reviewed against the implemented maintenance workflow on 2026-09-18.
This describes the process behind the [Legal & Transparency page](https://project-42.dev/legal-transparency/), not a guarantee that every claim is correct.

## Production and publication

The maintenance system has implemented discovery, currency inspection and reader
request intake. Scheduled inspection can identify gaps or outdated material and
prepare proposals. Human decisions govern entry into authoring and publication;
a queued, authored or approved proposal is not evidence that learners can see it.
A completed release also needs validation and deployment verification.

The automated authoring path uses research, writing, factual verification and
adversarial review roles. Cross-family and deployment-separation checks reduce
correlated errors. Failed factual review, missing evidence and unsupported
publication targets can hold work for repair. Reviewed direct repository repairs
also occur; they must not be represented as automated pipeline deliveries.

For the current public method, source-registry rules, role boundaries and known
limitations, see [how the curriculum stays current](https://github.com/project42dev/project42-platform/blob/main/docs/how-content-stays-current.md).
The implementation and operational records of the privately operated maintenance
service are not part of the public platform distribution.

## What learners receive

Research and generation happen before publication. Public lessons do not invoke
models while being read, and provider API keys are never included in browser
assets. Published material carries sources and verification dates. Those dates
identify a review point, not a promise that an upstream source cannot change.

Written instructor scripts, transcripts and captions are distinct from rendered
video. Media tooling exists, but video is available only for the modules whose
media has actually been produced and published. The [instructor production guide](https://github.com/project42dev/project42-platform/blob/main/docs/virtual-instructor-production.md)
explains the delivery contract.

## Limits and correction routes

Detection is not complete coverage, factual review can fail, proposals can be
blocked, and release checks cannot prove all prose is current. Learners should
check cited primary sources for consequential decisions. Report factual issues
or request material through [Support](https://project-42.dev/support/).
